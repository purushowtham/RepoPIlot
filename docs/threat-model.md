# Threat model and operational limits

Untrusted inputs include issue descriptions, repository code, model output, test output and HTTP IDs. The backend enforces schemas, ownership, diff context matching, path constraints, command allowlists, bounded retries and a persisted human decision. Repository text cannot confer tool permissions. Configured credentials and recognizable secret values are redacted; snapshots and generated diffs containing recognized secrets are rejected before checkpointing. Redaction is heuristic and cannot detect every secret: only use dedicated test repositories with no sensitive data.

Local demo mode uses deterministic outputs and explicitly labels every test result as a preview with a null exit code. It never calls the model, executes repository code or creates a GitHub branch/PR. Live publication additionally requires actual zero-exit test evidence and no blocking findings.

The Docker socket is available only to the trusted worker service in local Compose. This is substantial host authority. It is never mounted into the API, dashboard, or test containers, and models cannot invoke it. This MVP is for a private operator on a dedicated machine. The local account owner alone can configure or use live integrations. Credentials are Fernet-encrypted in a 0600 vault with a colocated 0600 key; this does not protect against compromise of the operator OS account. API request validation errors never echo submitted values. Production should place sandbox orchestration on a separate hardened host/service, add GitHub App installation authorization, request/auth rate limits, encrypted storage, resource/cost quotas, and dependency/image digest verification. Containers share a kernel and do not provide hostile multi-tenant isolation.

Cancellation is checked at workflow boundaries. A currently running model call or sandbox test completes or reaches its own timeout first. Cancellation is refused once a publish decision is committed because a GitHub mutation may already be underway. Compute duration is checked between nodes; individual HTTP requests have 30/60-second timeouts and retrieval has a total budget. Waiting for human approval does not consume the compute budget.

PR creation uses a stable per-run branch and checks existing open/closed PRs before creating one. Repeated identical decisions are idempotent; contradictory decisions return a conflict. If a retry encounters an existing branch, its tree and parent must match the approved pinned patch. GitHub writes cannot participate in the local database transaction, so crash recovery is best effort and may leave an unused Git object or branch. No merge/default-branch update is implemented.

Run history and source checkpoints are local data, not an encrypted vault. Use restrictive permissions and encrypted disks; use a secret manager for deployment. The signing key is generated with mode 0600 unless supplied through AUTH_SECRET. Never enable external tracing with sensitive repositories without auditing retention.
